# MathGuard — 论文 LaTeX 体检工具

**一个完全本地运行、不联网、不上传任何数据的 LaTeX 报错检查器。**

帮你抓出「编译能过、但印出来是空盒子 / 少括号 / 引用乱码 / 算错数」这类隐性错误。

## 怎么用（三步，不碰命令行）

1. 下载右侧 **Releases** 里的 `MathGuard-Windows-x64.zip`（33.5 MB），解压
2. 双击 **`MathGuard-GUI.exe`**
3. 把你的 `.tex` 文件或整个论文文件夹**拖进窗口**，点【开始体检】

几十秒后窗口里会显示结论：查明了几处、在哪一行。

**点一下报告里的行号**，会用你的编辑器（VS Code / Notepad++ / Sublime / TeXstudio / WinEdt）直接跳到那一行。

> 如果发现误报，请把出问题的那段 LaTeX 贴到 Issues 里。我负责修。

📖 **详细的使用说明与能力边界见 [使用说明.md](使用说明.md)**（压缩包里也带了一份）。

## 它能查什么

| 类型 | 例子 | 编译器会报错吗 |
|---|---|---|
| **空参数** | `\frac{a}{}`、`\binom{}{}`、`\sqrt{}` | ❌ 不报，印出来是空盒子 |
| **环境不配对** | 缺 `\end{equation}`、`\end{umerate}` 拼错 | 有时报，定位很差 |
| **括号不平衡** | `{` 多了少了、`\left` 缺 `\right` | 通常报但定位很差 |
| **引用断裂** | `\ref{eq:x}` 但 `eq:x` 不存在 | ❌ 不报，印出来是 `??` |
| **未引用标签统计** | 定义了 433 个标签，正文只引用了 204 个 | ❌ 不报，**纯客观计数** |
| **数值算错** | `2+2=5`、`1/2+1/3=2/5` | ❌ 不报，这是数学错误 |

**它不查**：证明对不对、推导逻辑、AI 式"审稿"，也**不评价**你的写作方式。
它只做**确定性校验**——查不出来就明说"我判定不了"，绝不冒充"通过"。

> **关于未引用标签**：工具只给出**数字和清单**，不判断这是"问题"还是"有意保留"。
> 数论论文里为了铺垫后续工作而定义引理、给中间公式命名却不直接引用，完全正常。
> **怎么处理由你决定，工具不发表意见。**

## 四态报告：不懂时不装懂

工具最大的问题不是算不出，而是**不懂装懂**。所以每条公式只有四种结论：

| 标记 | 含义 | 你该怎么做 |
|:---:|---|---|
| `[✓]` | 真的做过一次数值判定，且成立 | 放心 |
| `[✗]` | 数值关系**确定**不成立 | **必须修** |
| `[≈]` | 能读懂，但没有可判定的数字关系（纯符号、表格数据、同余式） | 工具没发现问题**不代表正确** |
| `[–]` | 超出能力（矩阵、多层求和、深层嵌套），已安全跳过 | 同上 |

**只有 `[✗]` 是可以断言"错"的。其余三种都不是"通过"。**

早期版本曾把"能解析"当成"验证通过"，结果一篇论文报出 232 条"通过"，其中 30 条只是表格里的 `64`、`(12,4)` 这类数据——毫无证明价值。现在只有真的做过判定，才配叫"通过"。

## 一个真实案例

某篇 55 页已定稿的论文，PDF 第 38 页公式 (7.16)：

```latex
\frac{-(e^{-x}-1)^{2}}{}      ← 分母是空的
```

**xelatex 编译 exit=0，日志 0 错误，PDF 里印成一道空横线。** 肉眼盯着看才看得出来。

工具扫出来报了 `\frac 的第 2 个参数为空`。同类问题在同一批源码里还有 4 处。

## 命令行用法

```cmd
math_guard.exe 你的论文.tex            :: 标准报告
math_guard.exe 你的论文.tex --lint     :: 额外查公式末尾缺标点（警告较多）
math_guard.exe 你的论文.tex --no-color :: 关颜色（重定向到文件时用）
math_guard.exe example.tex             :: 自测一下
```

### 批量检查整个文件夹（快 5-6 倍）

单篇启动约 1.3 秒，其中 ~0.7 秒是加载 sympy 的固定成本。要查多个文件时用 `--batch`：

```cmd
math_guard.exe --batch 论文目录\ -q        :: 一条命令查整个目录
math_guard.exe --batch a.tex b.tex         :: 指定多个文件
math_guard.exe --batch 目录\ -q --lint     :: 批处理 + 标点检查
```

实测对比（21 个文件）：

| 方式 | 耗时 | 平均 |
|---|---|---|
| 逐篇调用 | 27.4s | 1.30s/篇 |
| `--batch` | **4.6s** | **0.22s/篇** |

251 个文件批处理只需 **50 秒**。判定结果与逐篇调用完全一致。

### 从源码运行

```bash
pip install sympy
python math_guard.py 你的论文.tex
python math_guard_gui.py          # 图形界面
```

```bash
python math_guard.py paper.tex
case $? in
  0) echo "OK" ;;
  1) echo "仅有排版问题" ;;
  3) echo "数学错误，必须修" ; exit 1 ;;
esac
```

## 兼容性

| 情况 | 支持 | 说明 |
|---|:---:|---|
| UTF-8（含 BOM） | ✅ | |
| **GBK / GB18030** | ✅ | WinEdt + CJK 时代的老稿件直接可跑 |
| Big5 | ✅ | |
| 乱码（U+FFFD） | ⚠️ 视位置 | 在注释/正文里只警告；在公式里则拒绝，避免判定不可信 |
| 多文件（`\input`） | ✅ | 指向主文件，自动递归展开，报告显示真实 `文件:行号` |
| 自定义宏（`\def` / `\newcommand`） | ✅ | 自动收集并展开，含带参宏；`\renewcommand` 会正确覆盖 |
| 章节文件 | ⚠️ 会提示 | 误传章节文件时警告「这看起来是章节文件，主文件是 xxx」 |

### 为什么只接受 `.tex`

| 输入 | 公式能否还原 | 结构检查 | 结论 |
|---|:---:|:---:|---|
| `.tex` 源码 | ✅ | ✅ | **唯一可靠输入** |
| `.pdf` | ❌ 拆成排版碎片 | ❌ | 拒绝 |
| `.docx`（pandoc 转） | ⚠️ 仅 Office Math 公式 | ❌ 引用变纯文本 | 只能看公式 |

**PDF 实测**：把 PDF 文字层直接送进工具 → 提取 **0 条公式** → 报告"体检通过"。这是最坏的结果，所以工具会明确拒绝。

## 实测覆盖

| 来源 | 数量 | 结果 |
|---|---|---|
| arXiv 论文（8 个数学领域） | **125 篇** | 0 崩溃、0 误报 |
| 中文文档（ctex / CJK / ctexart） | **226 份** | 0 崩溃、0 误报 |
| 变异测试（在真实论文里植入错误） | 46 个 | 检出率 **100%** |
| 自测 | 132 项 | 全过 |

每个 bug 都来自真实文件，没有一个是想象出来的。修过的典型误报：

- `1/200=0.005` 被判错（`Fraction(1,200) == 0.005` 在 Python 里是 `False`）
- `26/500=5.2\%` 被判错（`\%` 被抹掉，变成 0.052 = 5.2）
- `5(5²-1)=120` 被判错（正则把 `(2-1)` 当成指数）
- `\bigl(\tfrac{3}{7}\bigr)=-1` 被当成 3/7=−1（勒让德符号只认 `\left...\right`）
- 注释里的 `\begin{equation}` 被当成真实环境
- `\def` 宏完全不支持，导致 `\sls{...}` 未展开、sympy 组合爆炸、整篇 5 分钟跑不完

## 已知边界

### 不做：验证定理/证明的正确性

`a²+b²=c²` 写成 `a²+b³=c²`，**工具分不出来**——两者都会归入 `[≈] 仅可解析`。

这类推导错误需要形式化证明器（Lean 4），不在本工具范围内。**工具只做确定性校验，不做数学推理。**

### 不做：「未定义符号」检查

原计划检查"某个单字母变量全文只出现一次且未定义"。实测数据否定了这个方案：

在两篇真实论文上找到的"全文只出现一次的单字母"共 3 个——`e`（自然常数）、`H`（正文有"乘 $H$ 修正"）、`M`（正文写作 `$\mathcal{M}$`）。**3 个全是误报，命中率 0%。**

### 不做：中英混排空格检查

不同期刊、不同模板风格差异极大，无法定义"正确"。

### 默认关闭：公式标点检查

检查行间公式末尾是否缺 `,` 或 `.`。实测 259 份文档产生 **309 条警告**，会淹没真正的问题。需加 `--lint` 显式开启。

### 刻意不报错的写法

- **勒让德/雅可比符号** `$\left(\frac{5}{11}\right)=1$`、`(3/7)=-1` —— 不是除法
- **导数记号** `${}'=d/d\tau$`、`\(f' =\) restriction of...` —— 是定义说明
- **章节标题里的记号** —— 用于指代，不是断言
- **邻近文字提到"取模"** —— 等号可能是模意义写法
- **多行公式的续行**：`$\displaystyle\Sigma_4(m)\equiv$`（以关系符结尾）
- **嵌在中文句中的符号代用**：`题设常数 $=2\times10^{-4}$`、`ESS$>1000$`
- **中文标签不等式**：`$\text{教育价值} \ge P_{75}$`
- **商集 / 循环小数 / 概率记号**：`T(H)/{\sim}`、`3122=\overline{1322}`、`\pr{...}`
- **TikZ 图形标签**：`\node ... {$w =$}`
- **远大于/远小于**：`n >> 0`
- **`\bigl`/`\bigr` 配对**：`\bigr|_{t=x}` 是合法的求值记号

## 自测

遵循**「一个永远报'通过'的防幻觉工具，本身就是幻觉」**的原则，本工具自带 132 项自测，其中包含它历史上真实犯过的错作为回归用例。

```bash
python test_math_guard.py        # 必须全过
python test_math_guard.py -v     # 显示每一条判定与理由
```

改任何判定逻辑后必须重跑。
