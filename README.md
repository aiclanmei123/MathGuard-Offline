# MathGuard-Offline

> 一个**纯离线**的 LaTeX 结构与公式数值校验工具，专为严谨的数学研究者设计。
> 我们拒绝用大模型做算术，只提供**绝对确定**的四态报告，杜绝任何假阳性幻觉。

## 一句话

把你论文的 `.tex` 丢进去，它会告诉你三件事：

1. **哪些标签是孤儿**（定义了却从没人引用）
2. **哪些引用是断的**（引用了不存在的标签）
3. **哪些数字算错了**（`2+2=5` 这种）

而且，**它不会骗你**——读不懂的公式会老实说"我没法判定"，绝不冒充"通过"。

---

## 核心设计：四态报告

这是本工具与所有"AI 科研助手"的根本区别——**工具不懂时不装懂**。

| 标记 | 状态 | 含义 | 你该怎么做 |
|:---:|---|---|---|
| `[✓]` | **已验证通过** | 确实做过一次确定的数字判定，且成立 | 放心 |
| `[✗]` | **验证失败** | 数字关系**确定**不成立。这是唯一可以断言"错"的状态 | **必须修** |
| `[≈]` | **仅可解析** | 能读懂（语法正确），但没有任何可判定的数字关系：表格数据、纯符号等式、同余式 | 工具没发现问题**不代表正确**，需人工判断 |
| `[–]` | **无法验证** | 超出当前能力（矩阵、多层求和、深层嵌套等），已安全跳过 | 同上，需人工判断 |

### 为什么要有 `[≈]`

早期版本曾把"能解析"当成"验证通过"，结果一篇论文报出 232 条"通过"，其中 30 条只是表格里的 `64`、`(12,4)` 这类数据——**毫无证明价值**。

现在的原则是：**只有真的做过判定，才配叫"通过"**。实测某篇论文 191 条公式里，真正被验证的只有个位数，其余都如实归入 `[≈]`。

### 一个真实案例

开发中曾出现如下 Bug：Python 3.13 起 `ast.literal_eval` 不再接受二元运算，`2+2` 抛异常被吞掉，判定环节静默跳过，最后返回了 `ok`——**`2 + 2 = 5` 被判为通过**。

这类"异常静默（silent failure）"是最危险的：工具看似正常，结论却是假的。现在改为白名单遍历求值，并有专门的回归测试锁定此问题。

## 快速开始

### 方式一：直接下 exe（无需 Python）

1. 下载 [MathGuard-Windows-x64.zip](https://github.com/USERNAME/MathGuard-Offline/releases/latest)（37.8 MB）
2. 解压到任意位置
3. 打开 cmd，cd 到该文件夹，运行：

```cmd
math_guard.exe 你的论文.tex
```

先自测一下：

```cmd
math_guard.exe example.tex
```

### 方式二：从源码跑

```bash
pip install sympy
python math_guard.py 你的论文.tex
```

可选增强（装了会做交叉校验，不装也能用）：

```bash
pip install latexnav parsub
```

## 使用

```bash
python math_guard.py paper.tex              # 标准报告
python math_guard.py paper.tex -v           # 列出每条被跳过/仅可解析的公式及原因
python math_guard.py paper.tex --no-color   # 关颜色（重定向到文件时用）
python math_guard.py --demo                 # 生成含预设错误的示例并体检
```

### 退出码

| 码 | 含义 |
|:---:|---|
| `0` | 干净 |
| `1` | **仅结构问题**（孤儿标签 / 未定义引用）——排版卫生 |
| `3` | **存在验证失败**（数字关系确定不成立）——内容错误，最严重 |
| `2` | 用法错误 |

分级的原因：CI 应当能区分"论文里公式算错了"和"有个标签没人引用"。

```bash
# 只在数学确实算错时才让流水线失败
python math_guard.py paper.tex
case $? in
  0) echo "OK" ;;
  1) echo "仅有排版问题" ;;
  3) echo "数学错误，必须修" ; exit 1 ;;
esac
```

## 特性

- **完全离线**：封死全部 socket 后仍可完整运行。无网络请求、无遥测、无 API key。
- **零假阳性优先**：宁可少报，不可错报。实测 251 份真实文档零崩溃，6 类历史误报全部修复并锁定为回归用例。
- **严格四态**：从不把"读懂了"伪装成"验证过了"。
- **内建宏库**：277 条 LaTeX 数学命令（`latex_macros.py`），离线、零依赖。
- **永不崩溃**：空文件、二进制乱码、6000 位大数、3000 层括号、GBK 编码等恶劣输入均安全退出。

## 兼容性

| 情况 | 支持 | 说明 |
|---|:---:|---|
| UTF-8（含 BOM） | ✅ | |
| **GBK / GB18030** | ✅ | WinEdt + CJK 时代的老稿件直接可跑 |
| Big5 | ✅ | |
| UTF-16 | ❌ 明确拒绝 | 检测到乱码会报错退出，**绝不静默给出"通过"** |
| 多文件（`\input`） | ✅ | 指向主文件，自动递归展开，报告显示真实 `文件:行号` |
| 自定义宏（`\newcommand`） | ✅ | 自动收集并展开，含带参宏 |

### 为什么只接受 `.tex`

| 输入 | 公式能否还原 | 结构检查 | 结论 |
|---|:---:|:---:|---|
| `.tex` 源码 | ✅ | ✅ | **唯一可靠输入** |
| `.pdf` | ❌ 拆成排版碎片 | ❌ | 拒绝 |
| `.docx`（pandoc 转） | ⚠️ 仅 Office Math 公式 | ❌ 引用变纯文本 | 只能看公式 |

**PDF 实测**：把 PDF 文字层直接送进工具 → 提取 **0 条公式** → 报告"体检通过"。这是最坏的结果，所以工具会明确拒绝。

**Word 部分可用**：

```bash
pandoc 论文.docx -t latex -o 论文.tex
python math_guard.py 论文.tex    # 公式能查，结构检查不可信
```

## 检查模块

| 模块 | 内容 | 级别 |
|---|---|---|
| **结构** | 孤儿标签 / 未定义引用 / 重复标签 | `[✗]` |
| **语法 · 环境配对** | `\begin`/`\end` 缺失、名字不符、嵌套错序 | `[✗]` 编译失败 |
| **语法 · 括号配对** | `{}` 与 `\left...\right` 用栈扫描 | `[✗]` 编译失败 |
| **排版 · 公式标点** | 行间公式末尾缺 `,` 或 `.`（中文标点也认） | `[!]` 警告 |
| **公式验证** | 数字关系自洽性（四态） | `[✓]/[✗]/[≈]/[–]` |

实测数据（259 份真实文档）：

- 语法错误：**6 个文件**，逐条核实**全部是真错误**（如 `\end{umerate}` 少个 n、`\binom{2t}{t}` 少个 `}`）
- 标点警告：93 个文件 / 309 条，抽样核实**大部分是真缺失**

## 自测

遵循**「一个永远报'通过'的防幻觉工具，本身就是幻觉」**的原则，本工具自带 31 项自测，其中包含它历史上真实犯过的错作为回归用例。

```bash
python test_math_guard.py        # 必须全过
python test_math_guard.py -v     # 显示每一条判定与理由
```

| 组别 | 内容 |
|---|---|
| A | 真错误必须抓到（`2+2=5`、`½+⅓=⅖` 等 5 条） |
| B | 真正确必须通过（否则全是噪音，5 条） |
| C | **历史误报回归**（勒让德符号、导数记号、不等式续行、幂后减号等 6 条） |
| D | 超能力范围必须承认（求和、纯符号、空公式，3 条） |
| R | 安全求值（Python 3.13 `literal_eval` 的回归，5 条） |
| — | 编码识别、宏展开、PDF 拒绝、退出码分级（7 条） |

改任何判定逻辑后必须重跑。

## 已知边界

以下情况**明确不做**，因为做了也只能靠猜或被误报淹没：

- **不验证定理/证明的正确性**：`a²+b²=c²` 写成 `a²+b³=c²`，工具分不出来——两者都会归入 `[≈] 仅可解析`。这需要形式化证明器（Lean 4），超出"确定性校验"的范围。
- **不接入任何知识库**：工具不做数学推理，只做结构与数值校验。（有意为之的产品边界）
- **不确定的 LaTeX 命令不猜**：自定义宏不会被强行赋予数学含义。
- **不做 PDF/Word 的"智能提取"**：会制造错误数据，宁可明确拒绝。
- **不做「未定义符号」检查**（模块四）：实测在 2 篇真实论文里找出的 3 个"全文只用一次的单字母"（`e`/`H`/`M`）**全部是误报**——`e` 是自然常数，`H`/`M` 在正文里定义过。数学论文里 `p` 默认素数、`α/β` 默认参数、`k/n/i` 到处用，这条规则的误报率无法接受。
- **不做中英混排空格检查**：不同期刊/模板风格不同，无法定义"正确"。
- **刻意不报错的写法**：勒让德符号 `(a/p)`、导数记号 `f'=d/dx`、章节标题里的记号、邻近文字提到"取模"的等式、不等式续行片段、嵌在中文句中的符号代用（如 `$=2\times10^{-4}$`、`ESS$>1000$`）。
- **`\bigl`/`\bigr` 不参与配对检查**：`\bigr|_{t=x}` 是合法的求值记号，强制配对会产生误报。这类漏检编译器会自己报。
